# Boss Escape 3D Interactive Program 제안서/PRD

## 1. 프로젝트 개요

### 1.1 프로젝트 기본 정보

- **프로젝트명:** Boss Escape
- **프로그램 유형:** 3차원 상호작용 프로그램
- **장르:** 3D 회피 액션
- **팀 구성:** 1인
- **개발 규모:** 전투 맵 1개, 플레이어 캐릭터 2종, 보스 3종, 최종 전투 1개
- **최종 제출 목표:** 2026년 12월 6일
- **발표 목표:** 2026년 12월 8일
- **제안서 제출:** 출력물 및 e-class 온라인 제출

본 프로젝트는 수업에서 요구하는 3차원 공간, 사용자 입력, 애니메이션, 시간에 따른 화면 변화, 게임 규칙, 화면 전환 및 종료 조건을 포함하는 인터랙티브 프로그램이다. 간단한 3D 객체와 효과를 사용하되, 조명·텍스처·반투명·카메라 연출을 적용해 컴퓨터 그래픽스 요소를 명확히 보여준다.

### 1.1.1 3D 모델링 및 에셋 제작 방식

- 일부 플레이어·보스·환경 객체는 **Blender 5.2**로 직접 모델링한다.
- Blender에서 제작한 모델은 **OBJ 파일**로 내보낸다.
- 생성된 OBJ 파일은 AI를 활용해 현재 프로젝트에서 사용할 수 있는 형태로 정리한다.
- 정리 대상은 프로젝트 좌표계에 맞는 크기와 방향, 원점 위치, 불필요한 구성요소, 파일 구조, 재질·텍스처 연결, 파일명 및 객체명이다.
- AI가 수정하거나 제안한 내용은 본인이 OBJ 재수입, 렌더링, 조명, 충돌, 애니메이션 적용 결과를 확인한 뒤 사용한다.

### 1.2 개인 작업 범위

| 담당 | 주요 작업 |
|---|---|
| 본인 | 기획, 3D 객체와 맵, 플레이어 이동, 체력/마나, 충돌, 필살기, 보스 AI, 조명, 반투명 효과, 카메라, HUD, 화면 전환, 테스트, 보고서 및 발표 |

1인 프로젝트이므로 시스템·그래픽스·문서 작업을 순차적으로 진행한다. 기능을 먼저 동작시키고, 이후 시각 효과와 장식 요소를 추가하는 방식으로 일정과 범위를 관리한다.

## 2. 프로젝트 목적 및 핵심 아이디어

### 2.1 배경과 플레이어 목표

플레이어는 제한된 전투 공간에 갇혀 세 명의 보스에게 동시에 또는 순차적으로 공격받는다. 보스의 공격을 피하면서 마나를 충전하고, 마나가 가득 차면 광역 필살기를 발동해 보스와 투사체를 제거한다. 모든 보스를 처치하고 최종 스테이지를 클리어하는 것이 목표다.

### 2.2 핵심 차별점

1. 일반적인 직접 공격 게임이 아니라 **공격 예측과 회피**가 중심이다.
2. 캐릭터마다 이동 속도, 필살기 비용, 반격 가능 여부가 다르다.
3. 현재 위치와 미래 이동 위치를 함께 노리는 보스 패턴을 사용한다.
4. 위험한 순간을 아슬아슬하게 피하거나 반격하면 마나를 더 얻는다.
5. 마나가 가득 찼을 때 캐릭터를 기준으로 카메라가 공전하며 광역 공격을 실행한다.
6. 마지막에는 활쟁이·검쟁이·힐러를 동시에 상대해 앞선 시스템을 종합한다.

## 3. 프로그램 진행 방법

### 3.1 전체 진행

1. 시작 화면에서 게임 시작 또는 종료를 선택한다.
2. 캐릭터 선택 화면에서 캐릭터를 선택한다.
3. 조작 안내가 표시된 전투 화면으로 이동한다.
4. 이동하며 보스의 공격 예고를 확인하고 회피한다.
5. 시간이 지나거나 위험 회피·반격에 성공하면 마나가 증가한다.
6. 마나가 최대치가 되면 필살기를 사용한다.
7. 스테이지의 모든 보스를 처치하면 다음 스테이지 또는 클리어 화면으로 전환한다.
8. 플레이어 체력이 0이 되면 게임 오버 화면으로 전환한다.
9. 클리어 또는 게임 오버 화면에서 재시작하거나 시작 화면으로 돌아간다.

### 3.2 조작

| 입력                  | 동작                           |
| --------------------- | ------------------------------ |
| WASD 또는 방향키      | 3D 전투 공간에서 플레이어 이동 |
| 마우스 이동/지정 방향 | 플레이어 방향 및 조준 보조     |
| Space                 | 마나가 최대일 때 광역 필살기   |
| Esc                   | 일시정지 화면                  |
| 화면 버튼 또는 Enter  | 시작, 재시작, 종료 선택        |

마우스 입력을 구현하지 못하는 경우 방향키 기반 이동과 Space·Esc만으로도 전체 플레이가 가능하도록 한다.

### 3.3 주요 규칙

- 플레이어 체력이 0이 되면 게임 오버다.
- 마나는 시간에 따라 천천히 증가한다.
- 공격을 근접해서 피하거나 반격하면 추가 마나를 얻는다.
- 필살기는 마나가 최대일 때만 사용할 수 있고 사용 후 마나는 0이 된다.
- 필살기 범위 안의 투사체는 제거되고, 보스는 피해를 입는다.
- 모든 보스를 처치하면 클리어한다.
- 모든 공격에는 바닥 범위, 방향선, 목표점 또는 보스 동작으로 된 사전 예고가 있다.

## 4. 스테이지·캐릭터·적 구성

### 4.1 스테이지

| 스테이지  | 내용                        | 완료 조건         |
| --------- | --------------------------- | ----------------- |
| 연습/시작 | 이동, 마나, 필살기 안내     | 전투 시작 선택    |
| 일반 전투 | 한 보스 또는 보스 패턴 일부 | 등장 보스 처치    |
| 최종 전투 | 3종 보스 동시 등장          | 세 보스 모두 처치 |

일정이 부족하면 별도의 연습 맵을 제거하고 시작 화면의 조작 안내와 하나의 전투 맵으로 통합한다.

### 4.2 플레이어 캐릭터

| 캐릭터 | 특징                                  | 플레이 방식                   |
| ------ | ------------------------------------- | ----------------------------- |
| 균형형 | 기본 이동속도·마나 비용              | 규칙을 처음 익히는 플레이어용 |
| 반격형 | 느리지만 반격 가능, 성공 시 마나 증가 | 공격 타이밍을 읽는 플레이     |
| 질주형 | 빠르지만 필살기 마나 비용이 큼        | 빠른 회피와 자원 관리         |

1인 개발 일정에 맞춰 캐릭터는 2종으로 확정한다. 각 캐릭터의 이동 속도와 마나 비용 또는 반격 가능 여부가 달라야 한다.

### 4.3 보스

| 보스   | 공격 및 지원 패턴                                   | 그래픽스 표현                            |
| ------ | --------------------------------------------------- | ---------------------------------------- |
| 활쟁이 | 현재 위치 1발, 예상 위치 2발, 특정 영역 화살비      | 화살 궤적, 목표점, 바닥 경고             |
| 검쟁이 | 회오리, 돌진, 부채꼴, 근접 범위 공격                | 공격 방향, 부채꼴 반투명 영역, 돌진 예고 |
| 힐러   | 자기 회복, 다른 보스 회복, 십자가 설치 및 지속 피해 | 회복 연결 효과, 십자가 조명, 피해 범위   |

보스는 각기 다른 색과 실루엣을 사용해 화면에서 구분한다. 공격 예고와 실제 충돌 판정은 분리해 플레이어가 대응할 시간을 확보한다.

## 5. 예상 화면 구성

1. **시작 화면:** 프로젝트명, 시작, 종료
2. **캐릭터 선택 화면:** 캐릭터 특성 및 조작 안내
3. **전투 화면:** 플레이어, 보스, 맵, 투사체, 공격 예고
4. **HUD:** 체력 게이지, 마나 게이지, 필살기 준비 상태, 현재 보스 상태
5. **일시정지 화면:** 계속하기, 재시작, 시작 화면
6. **게임 오버 화면:** 실패 원인, 재시작
7. **클리어 화면:** 처치 결과, 다시 플레이, 종료

전투 화면의 카메라는 플레이어와 전체 위험 영역을 함께 볼 수 있는 탑다운 또는 쿼터뷰로 구성한다. 필살기 사용 시 플레이어 주위를 카메라가 공전해 3D 공간감을 강조한다.

## 8. AI 활용 계획

### 8.1 사용할 AI와 활용 원칙

- **활용 도구:** GitHub Copilot 등 생성형 AI 도구
- AI는 자료 조사, 알고리즘 설명, 코드 초안, 오류 원인 후보, 테스트 아이디어를 얻는 보조 수단으로 사용한다.
- AI가 생성한 코드를 그대로 제출하지 않고 본인이 구조·수식·메모리 처리·입력 흐름을 직접 확인한다.
- 수업 요구사항과 프로젝트의 자체 설계를 우선하며, AI의 제안이 맞지 않으면 사용하지 않는다.
- 외부 에셋이나 코드 사용 시 라이선스와 출처를 확인한다.

### 8.2 AI 활용 작업 계획

| 작업           | AI 활용 계획                               | 본인이 직접 판단·수정할 부분            | 결과 확인 방법            |
| -------------- | ------------------------------------------ | ---------------------------------------- | ------------------------- |
| 이동·충돌     | 좌표 변환과 충돌 예제 질문                 | 프로젝트 좌표계, 속도, 경계값 결정       | 벽 충돌·대각선 이동 실행 |
| 보스 AI        | 상태 머신과 쿨다운 구조 초안 요청          | 공격 순서, 난이도, 공정한 예고 시간 결정 | 패턴 반복 및 회피 테스트  |
| 그래픽스 오류  | 컴파일/렌더링 오류 메시지의 원인 후보 확인 | 실제 리소스·API 버전과 대조해 수정      | 빌드와 화면 출력 확인     |
| Blender OBJ 에셋 정리 | OBJ의 임포트 오류, 좌표계·스케일·재질 문제를 해결하는 방법 질문 | 모델의 최종 형태, 폴리곤 수준, 원점과 충돌 기준 결정 | 프로젝트에서 재수입 후 렌더링·충돌·애니메이션 확인 |
| 셰이더·반투명 | 알파 블렌딩, 조명 적용 방법 조사           | 깊이 테스트와 렌더 순서 결정             | 겹치는 영역의 표시 확인   |
| 보고서·발표   | 문장 구조와 점검 목록 보조                 | 실제 구현 내용과 수치만 기재             | 실행 화면과 문서 대조     |

AI의 답변이 틀리거나 작동하지 않으면 오류를 재현하고, 공식 문서와 컴파일러 메시지를 기준으로 원인을 확인한 뒤 직접 수정한다. 해결되지 않는 코드를 무리하게 포함하지 않고 단순한 대체 구현으로 전환한다.

## 10. 테스트 및 완료 기준

### 10.1 기능 테스트

- 키보드 입력으로 이동하고 맵 경계를 벗어나지 않는다.
- 보스의 공격이 예고 후 발생하고 충돌 시에만 피해를 준다.
- 시간에 따라 애니메이션과 마나가 변화한다.
- 필살기가 최대 마나에서만 발동하고 투사체와 보스에 정상 적용된다.
- 체력이 0이면 게임 오버, 모든 보스가 처치되면 클리어 화면이 표시된다.
- 시작·선택·전투·일시정지·결과 화면을 오류 없이 이동한다.

### 10.2 그래픽스 테스트

- 3D 객체의 깊이와 조명 방향이 정상적으로 보인다.
- 반투명 공격 범위가 캐릭터·지면에 가려지지 않고 식별된다.
- 카메라 공전 후 원래 전투 시점으로 자연스럽게 복귀한다.
- 발표 컴퓨터에서 프레임 저하나 화면 잘림 없이 실행된다.

### 10.3 최소 완료 기준

- [ ] 3D 전투 공간과 사용자 입력이 구현되어 있다.
- [ ] 시간 기반 애니메이션과 상태 변화가 보인다.
- [ ] 최소 2종의 캐릭터가 서로 다르게 동작한다.
- [ ] 보스 3종의 대표 패턴이 구현되어 있다.
- [ ] 마나·필살기·투사체 제거가 동작한다.
- [ ] 시작부터 종료까지 화면 전환 흐름이 완성되어 있다.
- [ ] 클리어와 게임 오버 조건이 동작한다.
- [ ] 사용한 AI의 활용 범위와 직접 검증·수정 내용을 보고서에 기록한다.
