### 1.3 프로젝트 목적

본 프로젝트는 3차원 공간에서 사용자의 키보드 입력에 따라 캐릭터가 이동하고, 시간에 따라 보스의 공격과 애니메이션이 진행되며, 특정 조건에 따라 화면이 전환되는 인터랙티브 프로그램을 제작하는 것을 목적으로 한다.

단순한 3D 객체를 이용해 전투 공간과 캐릭터를 구성하고, 조명·텍스처·반투명 효과·카메라 연출을 적용해 컴퓨터 그래픽스의 특징을 표현한다.

### 1.3.1 3D 모델링 및 OBJ 에셋 제작

일부 플레이어·보스·환경 객체는 **Blender 5.2**를 이용해 직접 모델링한다. Blender에서 완성한 모델은 OBJ 파일로 내보내 현재 프로젝트에 적용한다.

생성된 OBJ 파일은 AI를 활용해 프로젝트에서 사용할 수 있는 형태로 다듬는다. 프로젝트 좌표계에 맞는 크기와 방향, 원점 위치, 불필요한 구성요소, 객체명, 파일 구조, 재질 및 텍스처 연결을 점검하고 정리한다. AI가 제안하거나 수정한 결과는 본인이 프로젝트에 다시 불러와 렌더링, 조명, 충돌, 애니메이션이 정상적으로 동작하는지 확인한다.

## 2. 프로젝트 배경 및 핵심 아이디어

### 2.1 배경

플레이어는 제한된 전투 공간에 들어가 세 종류의 보스에게 공격받는다. 보스의 공격은 일정한 예고 후 발생하므로 플레이어는 공격 범위와 방향을 확인하며 이동해야 한다.

### 2.2 플레이어의 목표

플레이어는 공격을 피하면서 마나를 충전하고, 마나가 가득 차면 광역 필살기를 사용한다. 필살기를 이용해 보스와 투사체를 제거하고, 최종적으로 모든 보스를 처치하는 것이 목표다.

### 2.3 핵심 특징

1. 직접 공격보다 보스 공격의 예측과 회피가 중심이다.
2. 시간에 따라 마나와 보스 공격 패턴이 변화한다.
3. 현재 위치와 미래 이동 위치를 함께 노리는 보스가 존재한다.
4. 아슬아슬한 회피 또는 반격 성공 시 추가 마나를 얻는다.
5. 필살기 사용 시 플레이어 중심으로 카메라가 공전한다.
6. 마지막에는 세 종류의 보스를 동시에 상대한다.

| 힐러   | 자기 회복, 다른 보스 회복, 십자가 설치 및 지속 피해 | 회복 대상과 십자가 범위를 우선 판단   |

보스마다 색상과 실루엣을 다르게 적용해 화면에서 구분할 수 있도록 한다.

## 4. 게임 진행 방법

### 4.1 진행 순서

1. 시작 화면에서 게임 시작을 선택한다.
2. 캐릭터를 선택하고 조작 안내를 확인한다.
3. 전투 화면에서 플레이어를 이동한다.
4. 보스의 공격 예고를 보고 위험 영역을 피한다.
5. 시간이 지나거나 회피·반격에 성공하면 마나가 증가한다.
6. 마나가 최대치가 되면 필살기를 사용한다.
7. 필살기로 보스에게 피해를 주고 투사체를 제거한다.
8. 모든 보스를 처치하면 클리어 화면으로 이동한다.
9. 체력이 0이 되면 게임 오버 화면으로 이동한다.

### 4.2 조작 방법

| 입력                       | 기능                           |
| -------------------------- | ------------------------------ |
| WASD 또는 방향키           | 3D 전투 공간에서 플레이어 이동 |
| 마우스 이동 또는 지정 방향 | 플레이어 방향 및 조준 보조     |
| Space                      | 마나가 최대일 때 필살기        |
| Esc                        | 일시정지 화면                  |
| Enter 또는 화면 버튼       | 시작·재시작·종료 선택        |

### 4.3 게임 규칙

- 플레이어 체력이 0이 되면 게임 오버다.
- 마나는 시간에 따라 천천히 증가한다.
- 공격을 가까이서 피하거나 반격하면 추가 마나를 얻는다.
- 필살기는 마나가 최대일 때만 사용할 수 있다.
- 필살기 사용 후 마나는 0으로 초기화된다.
- 필살기 범위 안의 투사체는 제거되고 보스는 피해를 입는다.
- 모든 보스를 처치하면 게임 클리어다.
- 모든 공격에는 바닥 범위, 방향선, 목표점 또는 보스 동작으로 된 예고가 있다.

## 8. 1인 개발 계획

모든 기획·프로그래밍·그래픽스·테스트·문서 작업은 본인이 담당한다. 작업 순서는 다음과 같다.

1. 동작 가능한 최소 전투를 먼저 구현한다.
2. 핵심 기능이 안정화된 뒤 보스 3종을 추가한다.
3. 공격 예고와 피격 피드백을 적용한다.
4. 조명, 텍스처, 반투명, 파티클을 추가한다.
5. 화면 전환과 발표용 UI를 완성한다.
6. 반복 테스트 후 실행 파일과 보고서를 고정한다.

일정이 부족하면 사운드·장식 효과를 먼저 줄이고, 캐릭터 선택 화면을 단순화하거나 캐릭터를 1종으로 통합한다. 3D 상호작용, 마나·필살기, 보스별 대표 패턴, 화면 전환·종료 조건은 유지한다.

## 11. 테스트 및 완료 기준

### 11.1 기능 테스트

- 키보드 입력으로 이동하고 맵 경계를 벗어나지 않는가?
- 보스 공격이 예고 후 발생하고 충돌 시에만 피해를 주는가?
- 시간에 따라 애니메이션과 마나가 변화하는가?
- 필살기가 최대 마나에서만 발동하는가?
- 필살기가 투사체를 제거하고 보스에게 피해를 주는가?
- 체력이 0이면 게임 오버 화면이 표시되는가?
- 모든 보스 처치 시 클리어 화면이 표시되는가?
- 시작·선택·전투·일시정지·결과 화면이 정상 전환되는가?

### 11.2 그래픽스 테스트

- 3D 객체의 깊이와 조명 방향이 정상적으로 보이는가?
- 반투명 공격 범위가 지면과 캐릭터에 가려지지 않는가?
- 카메라 공전 후 전투 카메라로 자연스럽게 복귀하는가?
- 발표 컴퓨터에서 프레임 저하나 화면 잘림 없이 실행되는가?

### 11.3 최종 완료 기준

- [ ] 3D 전투 공간과 사용자 입력이 구현되어 있다.
- [ ] 시간 기반 애니메이션과 상태 변화가 보인다.
- [ ] 캐릭터의 이동과 체력·마나가 정상 동작한다.
- [ ] 보스 3종의 대표 패턴이 구현되어 있다.
- [ ] 마나·필살기·투사체 제거가 동작한다.
- [ ] 시작부터 종료까지 화면 전환 흐름이 완성되어 있다.
- [ ] 클리어와 게임 오버 조건이 동작한다.
- [ ] 조명·텍스처·반투명·카메라 중 계획한 그래픽스 기술이 적용되어 있다.
- [ ] AI 활용 및 직접 검증·수정 내용이 기록되어 있다.
